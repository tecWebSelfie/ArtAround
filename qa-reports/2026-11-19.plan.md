## Flows to attack (risk order)

### D1 — Paid content body leaks (High risk)

- Pre: a paid content (price > 0) by author A, visitor B without purchase,
  anonymous.
- Steps: `GET /api/contents/:id`, `?depth=2`, `?select[body]=true`,
  `/api/contents/:id/localized`, GraphQL `Contents { body }`, `where[body][like]=…`
  (query oracle on a restricted field), `GET /api/content-variants?where[content]`,
  `/api/content-audio/:id` (audio of a paid body), `/api/expand`, `/api/speech`,
  `/api/assistant` with the content id, content page `/en/content/:id`, tour
  page including a paid stop, `versions` / drafts endpoints.
- Expected: no body, no audio, no derived text (variants, summaries) for a
  non-owner; filtering on `body` refused or meaningless.
- Failure: any byte of the body text, or a boolean oracle on it.

### D2 — Private content / tour exposure via lists and joins

- `GET /api/users/:id?depth=2` (joins `authoredContents`/`authoredTours`),
  `GET /api/museums/:id?depth=2`, `/api/navigator-search`, `/api/museum-mode`,
  `/en/user/:id`, `/en/search/*?author=`, GraphQL joins, `content-variants`
  of a private content, `content-audio` of a private content.
- Expected: private items of others never listed nor titled.

### D3 — Content editor writes (IDOR / mass assignment)

- B `PATCH /api/contents/<A's id>`, `PATCH` setting `author`, `createdBy`,
  `price`, `visibility`, `moderation` fields on own content; create with
  another `author`; `content-variants` create/update for A's content;
  `content-audio` regeneration for A's content; `DELETE` as a verified/curator of
  another museum; huge/null/wrong-type `title`, `body` (lexical JSON garbage),
  `price` negative / NaN / 1e308, duplicate concurrent creates.
- Expected: 403/400, never 500, no foreign writes.

### D4 — Profile (users)

- B `PATCH /api/users/<A>`; self-update of `roles`, `email` to an existing one,
  `username` collisions (case, unicode confusables, concurrent), avatar
  upload of another user's media, password change without current password,
  `GET /api/users?where[email][like]=` (oracle), `/api/users/me` fields,
  `/en/user/:id` with ids of non-existent / malformed values (500?).
- Expected: self-only writes, no email oracle, 4xx on garbage.

### D5 — Search routes without Typesense (outage path)

- `/api/navigator-search`, `/en/search/{tours,contents,objects}` with
  hostile params (`?author=` other's id, `?subject=` garbage, huge `q`,
  `filter_by` injection characters like `&&`, backticks, `:=`), since
  Typesense is not configured locally: must show the outage, never 500
  with a stack, never inject into `filter_by` (code reading of
  `src/lib/search/query.ts` / `src/lib/search-scope.ts`).

### D6 — AI routes (AI_MOCK) abuse

- `/api/assistant`, `/api/expand`, `/api/plan-tour`, `/api/speech`,
  `/api/transcribe`: anonymous use, ids of private/paid items in the
  context, huge bodies, wrong types. Expected: auth/rate rules as documented,
  no private/paid text echoed into the prompt or answer.

### D7 — Purchases / checkout

- `GET /api/purchases` other's rows, `POST /api/checkout` for own content,
  private content, price 0, unknown id, tour with private stops.
