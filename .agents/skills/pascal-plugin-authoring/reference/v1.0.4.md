# Pascal 1.0.4 Additions

Diffed from npm tarballs (`@pascal-app/*` 1.0.3 → 1.0.4). Plugin contract
(`Plugin`, `loadPlugin`, discovery, install gate, `apiVersion: 1`) is
**unchanged** — what follows is new optional surface for kind authors.

## New `NodeDefinition` Fields

- **`placementNotice?: (node, ctx) => PlacementNotice | null`** — "why the
  node doesn't fit where it stands". The editor shows `line` in the HUD's
  `"!"` row while the node is in hand, and `line` + `detail` at the top of
  its panel. A warning, never a block. Pure: `live` is the in-flight drag
  pose, merged in the kind's own frame. Return `null` when it fits.
  (`PlacementNotice = { line: string; detail?: string }`.)
- **`mechanism?: MechanismCapability`** — moving parts for **any** kind,
  plugins included: Play/Stop in the action menu, the `E` key, and the
  walkthrough read this instead of a kind name.
  `{ has(node), isOn(node, state), set(node, on), verb?: 'open' | 'run',
  icon?: 'door' | 'window' }`. Operating state is transient (`set` writes
  `useInteractive`, never the node) — running a mechanism never enters
  undo, autosave, or collaboration.
- **`batchable?: BatchableConfig`** — opt static kinds into draw batching:
  opaque single-material meshes join the level's shared `BatchedMesh`
  while static; sources stay mounted, pickable, exported.
  `{ scope: 'level' | 'wall', excluded?, settled?, batchKey?,
  waitsForWalls? }`. Only for kinds that are direct level children
  (`'level'`) or hosted by a visible wall (`'wall'`).
- **`roleLabel?: (node, role) => string | null`** — label override for a
  paint role that isn't a declared slot. Return `null` to keep the derived
  label.
- **`holesFor?: (ceiling) => Array<Array<[x, y]>>`** — holes this kind cuts
  in a `ceiling` that no child of it reports (e.g. a live move preview
  sitting on a ceiling it doesn't belong to yet).

Frozen contracts (declare for forward-compat, **not read yet** — no runtime
effect today): **`cuts?`** (`(node, ctx: CutsContext) => CutIntent[]`,
replaces `collectCutoutBrushes`/`roofAccessory.buildCut`/`ceilingCut`
later), **`refs?`** (`readonly ReferenceDeclaration[]`, future
clone/delete/split/preset extractor), **`assembly?`**
(`AssemblyHostConfig`, future wall/roof layer compilation).

## Changed Signatures (backward compatible)

- **`ports?: (node, ctx?: EvaluationContext) => NodePort[]`** — new optional
  second arg; hosts must always pass it, impls fall back to the stored pose
  when absent. Existing one-arg impls still compile.
- **`selectable?: SelectableConfig | false`** — can now be `false` to make a
  kind unpickable.
- **`reconcile?: (prev, next, nodes) => …`** — third arg carries all pending
  edits in the gesture, so reconciliation can read updated siblings during
  a multi-edit.
- **`collides?: boolean | ((node: AnyNode) => boolean)`** (inside
  `floorPlaced`) — predicate form per node (a block collides only while it
  rests on the floor). Always read it through the new registry helper
  **`floorPlacedCollides(floorPlaced, node)`** (`registry.d.ts`), not by
  reading the field.
- **`GeometryContext`** gains optional `surfaceHeightAt?(hostId, x, z)` and
  `supportHeightAt?(x, z, selectedHostId?)` — use when available, guard
  when absent (older hosts omit them).

## New Built-in Kinds (scaffold references)

- **`separator`** (`structure`) — 2D divider line (`bake: 'strip'`,
  `dirtyTracking: false`, `rendersChildren: false`, parametric renderer).
  Minimal example of a plan-only annotation kind.
- **`floor-opening`** (`structure`) — polygon void with full
  `floorplanAffordances` (`move-vertex`/`add-vertex`/`move-edge`): the
  current canonical example for polygon-vertex editing — copy it before
  inventing vertex handles for a custom polygon kind (e.g. service-room
  boundary editing).
- **`fence-feature`** — gates/openings hosted on fences: example of
  `parametrics` with a custom editor component, a `move-session` module,
  an `interaction` module, and a `floorplanMoveTarget` requiring
  `SceneApi` (throws without it).

## Recommended `defaults()` Pattern

New 1.0.4 built-ins derive defaults from the schema instead of hand-listing
fields — prefer this; it can't drift from the Zod shape:

```ts
defaults: () => {
  const { id: _id, type: _type, ...rest } = SeparatorNode.parse({
    start: [0, 0],
    end: [1, 0],
  })
  return rest
},
```

(Still never include `id`/`type`; still include the `BaseNode` defaults —
this pattern includes them automatically.)

## Notes

- Material color helpers are new core exports (`materialColorPaint`,
  `parseMaterialColor`, `slotPaintMaterial`, `slotDefaultPaintMaterial`),
  but the v1 limit stands: materials come from the library/scene refs —
  there is still no API to register custom materials.
- Core also grew internal planning libraries (wall assembly, stair
  sizing/presets, room topology, structure kernel, `commands/structure`,
  `node-slots`) with **no plugin-facing contract change**; ignore them
  unless a capability doc points at one.
